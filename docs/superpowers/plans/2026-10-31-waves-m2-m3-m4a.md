# Waves: M2 + M3, then M4a, Implementation Plan

> **For agentic workers:** REQUIRED: run this plan with the project skill
> `running-a-milestone` (`.claude/skills/running-a-milestone/SKILL.md`). Tasks 0–1 and 5 are
> the controller's (Mac loop and contracts commits), Tasks A1–C1 are wave 1's build round
> and C2–C5 wave 2's, each brief following the skill's §3. Tasks 4 and 7 are the merge,
> check, fix and ship rounds, cut down as the Global Constraints say. Steps use checkbox
> (`- [ ]`) syntax for tracking.

**Goal:** In one evening, ship the look (M2) and complete import (M3) as TestFlight
build 3, then the paged reader engine (M4a) as build 4. Ship things that work, and test
only what could lose KaiC's data.

**Architecture:**

- **Wave 1:** M2 and M3 run as one build round of 9 agents. The round also includes M4a's
  Core Text engine, which only creates new files. Two contracts commits sit underneath,
  one per wave, holding every file two agents would share. Each agent owns a disjoint
  set of files.
- **Wave 2:** M4a's reader screens, built by 4 agents on top of wave 1, the build 2 reader
  fix and the engine.
- **The Mac:** a rented Apple-silicon Mac (`ssh macrent`) is the integration check after
  every merge: build, demo screenshots, ShioriLibrary tests and the reader UI tests. CI
  and TestFlight still run from `main`.

**Tech Stack:**
- SwiftUI, iOS 26.0 minimum, Swift 5 mode, XcodeGen.
- GRDB, ZIPFoundation and SwiftSoup.
- System frameworks only beyond those: PDFKit, PhotosUI, Core Text.
- GitHub Actions `xcode-27` with Xcode 27.1, and Xcode 27.1 on the Mac.

**Spec:** `docs/superpowers/specs/2026-10-31-shiori-design.md`: §4, §5.1, §7.1–7.4, §7.7's
Aa sheet, §8 and §9. Roadmap entries: M2, M3 and M4a in `docs/roadmap.md`.

## Global Constraints

- **Platform:**
  - iOS 26.0 minimum, built with Xcode 27.1.
  - iOS 27-only APIs go behind `if #available(iOS 27, *)`.
  - Swift 5 language mode, and no project-level xcconfig.
- **Layout:** never hard-code the 17 Pro Max's 440 pt. Lay out from the available size.
- **Colour:** tokens only (§4.2), never a literal colour in a view.
- **Glass:** only on the floating layer: the bar, the reader's top bar and dock, and
  floating buttons. Tint it with `paper`. Everything else is solid paper.
- **Shape:** radii are 4 pt for panels, 8 pt for cards and rows, and capsules for floating
  controls (§4.3).
- **Motion:**
  - Every animation reads `@Environment(\.motionReduced)`, which is true under the
    system's Reduce Motion or Shiori's own switch. When it's true, the animation becomes a
    short crossfade.
  - Nobody reads `accessibilityReduceMotion` directly any more.
- **Haptics:** only through the `.shioriHaptic(_:trigger:)` modifier, which respects the
  Settings switch.
- **Strings:**
  - Every user-facing string is in `Localizable.xcstrings` in English and `zh-Hans`.
  - Strings made outside SwiftUI views (toasts, outcome text) use
    `LocalizedStringResource`, so the in-app language applies.
  - An agent that needs a new string uses it, then lists it with its translation in its
    report.
- **No network:** no network requests, analytics or crash SDKs. Pick from a photo uses
  `PhotosPicker`, which needs no permission prompt.
- **Dependencies:** no new packages.
- **Clean-room:**
  - never open, translate or copy code from `Wenku8_Flutter`, `Shiori-Flutter` or
    `mikufoxxx/Wenku8_Flutter`
  - `reference/screens/` and `docs/design/concepts/` are for look and feel only
  - never trace the old app's icons
- **Fixtures:** sample text is generated, never long passages of an existing work. KaiC's
  books never enter the repo.
- **Comments:** sparse and why-not-what, with no section dividers and no "Note:".
- **File ownership is the merge contract:**
  - An agent edits only its **Owns** files and reports any other need.
  - Only the controller edits the shared files: `project.yml`,
    `tools/app-check/Package.swift`, `Localizable.xcstrings`, `ios-compile.yml`,
    `tools/shots.sh`, `tools/mac/*`, `AppModel.swift`, `ShioriApp.swift`,
    `RootView.swift`, `DemoLaunch.swift`, `Tokens.swift`, `AppSettings.swift`,
    `Motion.swift`, `Haptics.swift`, `Icons/ShioriIcon.swift`,
    `Icons/IconGalleryView.swift`, `ImportOutcome.swift`, `ImportSettings.swift`,
    `Records.swift`, `Records+M3.swift`, `LibraryDatabase.swift`,
    `ReaderTypography.swift`, `ReaderPreferences.swift` and `DemoBooks.swift`.
  - `ImportInbox`'s current API is frozen: B2 calls it, and B3 may only add to it.
- **Agents' gate:**
  - `bash tools/check-app.sh` prints OK.
  - `swift test` passes in `ios/Packages/ShioriCore` if the agent touched ShioriCore.
  - `bash tools/check-lib-tests.sh` is OK if it touched ShioriLibrary.
  - Agents never push, merge or switch branches.
- **Light testing:**
  - A slice is done when it compiles, launches, and its screen shows it working in the
    controller's Mac screenshot.
  - Tests are written only where a bug would cost KaiC's data:
    - updates in place, remapping progress by chapter key
    - removal memory
    - ZIP name and TXT encoding decoding
    - TXT re-split
    - the paginator's position mapping
    - the paged reader keeping its place across a size change
  - No per-behaviour TDD anywhere else.

## Review Focus

1. **An update whose chapters repeat titles, or whose identifier matches while the title
   changed:**
   - it must update the existing book, not add a duplicate
   - progress remaps by `(keyTitle, keyOccurrence)` and falls back to the clamped index
   - B1's `BookUpdateTests`
2. **A watched folder's bookmark goes stale** (the folder was moved or renamed, or the app
   was reinstalled):
   - the card says "Folder unavailable. Choose it again."
   - a scan never silently does nothing
   - B2; the controller checks it on the Mac by deleting the demo folder
3. **iCloud placeholders** (`.Name.epub.icloud`):
   - never imported as files
   - a download is started, the log says "Waiting for iCloud download", and the next scan
     picks the file up
   - B2
4. **The in-app language versus text built outside views:** toast and outcome text must
   follow Settings → Language, not the phone's language.
   - A3 and B2/B3 use `LocalizedStringResource`
   - shot 09 is taken in English on a Chinese simulator
5. **Changing the type size in the paged layout keeps the paragraph on screen:**
   - C1's `PaginatorTests.offsetSurvivesRelayout`
   - C3's `ReaderPagedTests.testSizeChangeKeepsPlace`

## The Mac loop

**Machine:**
- A rented Apple-silicon Mac, reached as `ssh macrent`. The host entry is already in
  `~/.ssh/config`.
- It has Xcode 27.1 and an iPhone 17 Pro Max simulator on the newest iOS runtime.
- It never holds signing keys, App Store Connect keys or an Apple ID.

**Code:**
- `dev` reaches it with `git push macrent dev`, into `~/Shiori`, a non-bare repo set to
  `receive.denyCurrentBranch updateInstead`.
- This never touches GitHub, so the Branches rule still holds.

**Test book:** lives at `~/Books/` on the Mac, outside the repo. To load it, copy it into
the simulator app's Documents folder
(`xcrun simctl get_app_container booted com.kaichuan.shiori data`), then tap
"Use Shiori's own folder" and Scan now. That's M3's own path.

**Who uses it:** only the controller. Agents compile locally with `check-app.sh`, because
one Mac can't take nine builds at once.

### Task 0: Mac loop scripts (controller)

**Files:** create `tools/shots.sh`, `tools/mac/run.sh` and `tools/mac/setup.sh`, and modify
`.github/workflows/ios-compile.yml`.

**Produces:**
- **`tools/shots.sh <udid> <outdir>`:** the one shot list, used by both CI and the Mac. It
  moves CI's `shot`/`shoot` functions and lines here, so the two can't drift apart.
- **`tools/mac/setup.sh`:** a one-time, idempotent setup.
  - It runs `xcodebuild -runFirstLaunch` and installs `xcodegen` with brew.
  - It creates `~/Shiori` with the `updateInstead` config and adds the `macrent` remote
    locally.
  - It creates the simulator and boots it.
- **`tools/mac/run.sh build|shots|libtests|uitests|all`:**
  - First it pushes `dev` to the Mac.
  - Then it runs on the Mac:
    - `xcodegen generate --spec project-tests.yml`
    - the same `xcodebuild` command line as CI, in Debug
    - and, per argument: `tools/shots.sh`, `swift test` for both packages, and
      `xcodebuild test -scheme ShioriUITests`
  - It copies `shots/` back to `.superpowers/mac-shots/<time>/`, which is gitignored.
  - It prints only test summaries and errors.

- [ ] Write the scripts, then run `setup.sh` once and `run.sh all` once on the current `dev`.
  Expected: the M1 screenshots appear locally, and the four reader scroll tests run.
- [ ] Commit: "Run the build, screenshots and tests on a Mac over SSH".

### Task B1: Import engine

**Spec:** §8.3 (pipeline, ZIP, PDF, limits), §8.4, §7.3's position remap, and the M3

**Builds** (all in ShioriLibrary):
- **`importFiles(at:origin:settings:)`:**
  - ZIPs are expanded into staging. GBK/GB18030 names are decoded when the entry's UTF-8
    flag (bit 11) is off and the name isn't valid UTF-8.
  - Supported entries are imported one by one, and a nested `.zip` gives

  - The limits are 512 MiB for ZIP and PDF.
- **PDF:**
  - stored like any book, as `original.pdf`
  - title and author from `PDFDocument.documentAttributes`, else `FileNameMetadata`
  - the cover is a first-page thumbnail at 600 px tall, saved as `cover.jpg`
  - `chapterCount` 0 is allowed for PDF only
- **TXT:**
  - `settings.encoding` overrides detection (`.auto` keeps M1's detection)
  - `settings.rules` replaces the presets
- **Updates in place (§8.4)**, checked before inserting:
  - The book matches by EPUB `sourceIdentifier`, else by `titleAuthorKey`.
  - A different hash means: swap `original.*`, rebuild the chapters, and remap `progress`
    by `(keyTitle, keyOccurrence)` using `ReadingPosition.chapterIndex`, keeping the
    offset.

    grow), and returns `.updated`.
  - The swap is crash-safe, the same way as M1: build in staging, then move, then write
    the rows in one transaction.

    `removedBook`.

- **`resplit(bookId:settings:)`:** TXT only. It re-decodes the stored original with

  `.resplit`.

### Task C2: Paged views

**Spec:** §7.2, items 1 and 3; §7.6's standard tap zones only.

**Owns:** `App/Reader/Paged/`, holding these files:
- `PagedReaderView.swift`
- `PageCanvas.swift`, which draws a `CTFrame` in a `UIView`
- `RelayTurn.swift`
- `CurlPages.swift`, a `UIPageViewController(.pageCurl)` wrapper

**Builds:**
- **Page:** each page draws its frame from `ChapterLayout`, on `paper`. It asks the
  source for the neighbouring chapter's layout when you reach either end.
- **Tap zones (standard):**
  - left third: back
  - right third: forward
  - centre: `onCenterTap`
- **Swipes** turn pages. Every turn calls `onTurn` and fires the selection haptic.
- **Relay:**
  - The paper stays still.
  - The outgoing page's lines, grouped by paragraph, slide out in the turn direction in a
    stagger, and the incoming page's slide in the same way.
  - During a drag the motion follows the finger. A tap plays it in full.
  - Durations for gentle, standard and brisk:
    - per paragraph: 0.30, 0.22 and 0.16 s
    - stagger: 0.05, 0.035 and 0.025 s
- **Curl:** Apple's own timing. Speed doesn't apply, and the picker hides speed for Curl.
- **Reduce motion:** every effect becomes a 0.15 s crossfade.
- **Position:** `position` updates to the shown page's `range.lowerBound`.

## Planner's calls (made here; revisit with a reason)

1. **Instant language switch:** the `\.locale` environment at the root, plus `AppleLanguages`
   written for the next cold launch. Text built outside views uses
   `LocalizedStringResource`.
2. **Accent:** delivered as an `\.accent` environment value plus `.tint`, never a global.
3. **Icon drawing:**
   - Icons are `Canvas` drawings through `IconPainter`, split into two group files.
   - `activity` animates 0 to 1 on activation and stays at 1 while active.
   - The gallery shows both ends.
4. **Settings sub-pages:** they zoom out of their row (`navigationTransition(.zoom)`).
5. **Database:** one v2 migration holds every M3 table, and v3 holds sessions.
6. **Book identity for updates:** the EPUB identifier first, then `titleAuthorKey`. For TXT,
   `titleAuthorKey` only.
7. **Removal memory:**
   - keyed by content hash and identity key
   - blocks only the watched folder
   - cleared by a manual import
8. **The Updated badge:** shows until the book is next read (its `lastUpdatedAt` is newer
   than its progress), with no extra column.
9. **ZIP names:** decoded as GB18030 when the UTF-8 flag is off and the bytes aren't valid
   UTF-8.
10. **Scan skips:** by a `scannedFile` record of path, size and date; then the importer's hash
    check catches the rest.
11. **Text engine:**
    - Core Text both lays out and draws pages, so what's measured is what's shown.
    - The pagination cache is in memory (NSCache, 24 chapters), allowed by §10 and §16.
12. **Typography defaults:**
    - size 18, weight regular, line height 1.7, letter spacing 0
    - margins 24/24/16/16, paragraph gap 12
    - indent on, justify on
    - line-spacing presets 1.4, 1.7 and 2.0
13. **Relay timings:** as in Task C2. Apple's curl can't change speed, so speed is
    relay-only (a small spec clash, §7.2).
14. **Per-book typography:** stored in UserDefaults keyed by book id, since §10 puts
    "simple preferences" in UserDefaults.
15. **Font list:** built from the installed families that cover CJK, never a hard-coded
    list.
16. **Agent count:** round 1 has 9 agents, one above the comfortable 8, so the icons get two
    agents.

**Nothing in the spec blocks a slice.**
- §9's summary header waits for M8's stats, which the roadmap already says.
- §7.4's downloadable fonts and §7.5's themes stay in M4b.
